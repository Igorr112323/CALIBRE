# Android-приложение КАЛИБР — этап 3

Приложение упаковывает интерфейс локально в APK через Capacitor. Каталог, схема и карточки остаются на устройстве без сети; отзывы и вопросы сохраняются в очереди и отправляются при восстановлении соединения. Публичный сайт приложения не создаётся.

## Сборка APK в Windows одной командой

### Что потребуется один раз

- Windows 10/11.
- Node.js **22 LTS** с npm.
- Android Studio со стандартными Android SDK / Platform Tools / Build Tools.
- JDK 21 (встроенный JBR Android Studio подойдёт).
- Интернет для первоначальной загрузки npm-пакетов, Gradle и компонентов Android SDK. После подготовки сохранённые зависимости можно использовать локально.

### Сборка

1. Распакуйте или скопируйте весь проект в папку на компьютере.
2. Откройте `build_apk.bat` двойным щелчком либо из командной строки. Он выполнит `npm ci`, соберёт интерфейс, синхронизирует Capacitor Android-проект и запустит Gradle.
3. При запросе Android SDK/JDK укажите установленный SDK и JDK 21. Первый Gradle-запуск может загрузить компоненты; дождитесь окончания.
4. Готовый отладочный APK должен появиться здесь: `dist\CALIBRE-debug.apk`.
5. Если сборка завершилась ошибкой, сохраните текст окна и проверьте версии Node/JDK/SDK. Скрипт не подписывает APK для публикации и не создаёт release-keystore.

### Установка на Android

1. Передайте `dist\CALIBRE-debug.apk` на телефон по USB (или другим личным способом).
2. На телефоне откройте APK файловым менеджером. Android может попросить разрешить установку приложений из этого источника — разрешите её для выбранного файлового менеджера и подтвердите установку.
3. Откройте **КАЛИБР**. Для наполнения каталога подключите компьютер-сервер и телефон к одной доверенной Wi-Fi-сети.
4. Запустите `run.bat` на серверном компьютере. В его окне найдите адрес для приложения, например `http://192.168.1.20:8765`.
5. В приложении откройте **Настройки**, впишите именно этот адрес (не `127.0.0.1`), нажмите **Проверить связь**, затем **Синхронизировать**. Запомните дату последней синхронизации.
6. Если Windows Firewall спросит, разрешайте входящее соединение Python только для частной сети, которой доверяете. Не включайте проброс порта на роутере и не делайте сервер доступным из интернета.

### Проверка офлайн-режима и очереди

1. Выполните синхронизацию и убедитесь, что карточки появились в **Машины**.
2. Включите на телефоне авиарежим. Откройте карточку, схему, список узлов и пример проблемы: уже полученные сведения должны оставаться доступными.
3. Нажмите вариант ответа в **«Помогла карточка?»** или создайте вопрос экспертам. В настройках появится число записей в очереди.
4. Отключите авиарежим и верните телефон в ту же сеть. Приложение попробует отправить записи автоматически; при необходимости нажмите **Синхронизировать**. Очередь уменьшается после подтверждения сервером.
5. Этот набор содержит явно помеченные **ДЕМО**-карточки для проверки интерфейса. Числовых настроек для настоящей косилки в нём нет — не используйте его для регулировки техники.

Проверка Windows/телефона должна выполняться владельцем оборудования: сборка и физическая установка в текущей среде не подтверждены.

## Предпросмотр на компьютере без APK

1. При желании отдельно запустите `run.bat`, чтобы локальный сервер и каталог были доступны браузеру.
2. Запустите `preview_app.bat` и откройте `http://127.0.0.1:5173` **на том же компьютере**.
3. Предпросмотр Vite специально привязан к `127.0.0.1`; он не слушает сетевой интерфейс и не предназначен для телефона/других устройств.
4. В браузере используется IndexedDB, а при её недоступности — резервный `localStorage`. В APK используется нативная SQLite; если плагин не откроется, предусмотрен резерв IndexedDB.
5. Это отдельный браузерный просмотр; APK строится только `build_apk.bat`.

## Хранилище и синхронизация

- Android: локальный снимок каталога, параметры подключения и очереди хранятся в SQLite в приватной области приложения. Файлы интерфейса уже находятся внутри APK.
- Браузерный предпросмотр: IndexedDB; резерв — `localStorage`. Это сделано вместо браузерного режима SQLite, для которого потребовались бы дополнительные sql.js/jeep-sqlite-компоненты.
- Сервер: `GET /api/mobile/sync` выдаёт опубликованный каталог с ревизией; одинаковая ревизия не передаёт снимок повторно. Неопубликованные записи не попадают в приложение.
- С телефона разрешены только предусмотренные отправки `POST /api/mobile/feedback` и `POST /api/mobile/questions`; публикация, администрирование и произвольные изменения закрыты. Очереди используют идентификаторы событий, чтобы повторная отправка не создавала дубликат при потере ответа.
- Авиарежим не удаляет локальные данные. При возвращении сети срабатывают события браузера/Android Network; отправка также доступна вручную через настройки.
- В Android manifest разрешён обычный HTTP для связи с локальным сервером. Это настройка Android-приложения, а не рекомендация выставлять сервер в интернет.

## Разработчику

Из `mobile/`:

```powershell
npm ci
npm run build
npx cap sync android
```

Локальный предпросмотр запускается только на loopback:

```powershell
npm run dev:local
```

Лицензионные сведения и notices для прямых компонентов записаны в [`../THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md). Перед коммерческим выпуском нужен повторный анализ фактического графа зависимостей и прав на загружаемые документы/изображения. APK на этом этапе не собирался в проверочной среде.

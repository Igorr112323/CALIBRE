# КАЛИБР — локальный демо-срез ГРН-471 Kolibri v4

Ограниченная проверка этапов 4–6: PDF загружается на ПК, локально разбирается в фоне, карточки проходят проверку администратора, а телефон получает только выбранные опубликованные сведения. Это демо, не готовая универсальная база инструкций.

## ПК-админка и PDF

Windows EXE запускает локальный сервер и открывает админку в браузере. Исходный PDF и извлечённые страницы остаются на компьютере пользователя. Для точного руководства ГРН-471 Kolibri v4 начальный охват — текст руководства PDF-стр. 4–33; каталог деталей PDF-стр. 34–56. Каталог годится для названий деталей, но не для регулировочных норм.

После загрузки документ разбирается в возобновляемой фоновой задаче со статусом и прогрессом. Администратор видит карточки, страницу и цитату, может редактировать или отклонять их и отдельно публиковать подтверждённое. Все числовые факты проходят машинную проверку цитаты/страницы/числа; конфликтующие числовые дубли блокируются. Пробелы руководства, включая отсутствие абсолютной нормы высоты граблин над землёй, не заполняются догадками.

Админка содержит локальные настройки Ollama: `qwen3:8b` для извлечения и вопросов, `bge-m3` для векторного поиска. Модели не встроены в EXE/APK и загружаются через установленный Ollama. После установки выводы выполняются на компьютере через loopback, без облачного fallback. Без Ollama остаются PDF-просмотр, подготовленные материалы и лексический поиск; ответы генеративной модели не симулируются. Помощник не является обученной на PDF моделью.

Детали реализации, проверок, границ цитирования и локального benchmark — [`ADMIN_AI.md`](ADMIN_AI.md).

## Android APK, офлайн и sync

APK включает подготовленный текстовый демо-каталог **«ГРН-471 Kolibri (демо)»** и доступен офлайн. Существующие мобильные экраны и дизайн из `stage3-test-19` заморожены: структура, палитра, шрифты, анимация, иконка и заставка не меняются; можно только заполнить существующие области демо-контентом и добавить согласованную нажимаемую SVG-схему во вкладке «Схема». Вопросы по PDF находятся только в админке ПК.

При подключении к компьютеру по LAN телефон синхронизирует опубликованный каталог. Фото с правами `internal_only` передаётся только если администратор явно отметил разрешение LAN-sync, и только для опубликованного узла; это не публикация в интернете. PDF, черновики и админские функции наружу не выдаются. Локальный поиск, кэш согласованных фото, очередь отзывов и их отправка после восстановления связи поддерживают офлайн-работу.

## Файлы и сборки

Workflow `.github/workflows/build-android.yml` вручную собирает APK и Windows EXE, выполняет Windows self-test и формирует prerelease с прямыми ссылками и `SHA256SUMS.txt`. Для локальной сборки APK используйте инструкцию [`mobile/README.md`](mobile/README.md). Windows-зависимости перечислены в `requirements-desktop.txt`; PyInstaller собирает EXE вместе с приложением и локальными Python-компонентами.

Исходный PDF, извлечённые фигуры/кропы, локальная база и gold-эталон не входят в Git или релиз. Пользователь загружает свой PDF только после запуска EXE.

## Локальный сервер разработки

```bash
python -m pip install -r requirements.txt
python server.py
```

Админка: `http://127.0.0.1:8765/admin`. Данные сохраняются в `data/` при запуске из исходников; в Windows EXE — в `%LOCALAPPDATA%\CALIBRE`. Для LAN-синхронизации подключите ПК и телефон к одной частной Wi-Fi-сети и не открывайте админ-порт в интернет.

## Автоматические проверки

```bash
.venv/bin/python -m compileall -q calibre server.py desktop_launcher.py migrations/versions
.venv/bin/python -m unittest discover -s tests -v
node --check web/admin/admin.js
node --check web/admin/pdf-viewer.js
```

Результаты unit-тестов, Windows/Android сборок, gold-сверки и benchmark публикуются отдельно после их фактического запуска. Успех тестов в исходниках не означает, что APK установили на телефон или что Windows EXE запущен владельцем.

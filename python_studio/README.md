# Kolibri Python Studio

Локальный конструктор офлайн-справочника сельскохозяйственной техники: импорт руководств PDF, просмотр и редактирование каталога, локальный ИИ и сборка Android APK без Android SDK, Java, GitHub Actions или компилятора на этапе сборки. В комплекте — оболочка Android, её исходники и эталон ГРН-471: 8 групп и 124 позиции деталей.

## Быстрый запуск

1. Распакуйте архив в папку, в которой есть право записи.
2. Установите Python **3.10–3.12 x64** с `pip` и `venv`. На Windows используйте установщик с python.org и включите Python Launcher или добавление в PATH.
3. Windows: дважды нажмите `start.bat`. Linux/macOS: выполните `./start.sh`.
4. При первом запуске установятся Python-зависимости из PyPI. Откроется `http://127.0.0.1:8765/`. Оставьте окно терминала открытым; остановка — Ctrl+C.

Для принудительного запуска без браузера задайте `KOLIBRI_NO_BROWSER=1`. Для разработки можно изменить адрес и порт через `KOLIBRI_HOST` и `KOLIBRI_PORT`; по умолчанию сервер доступен только этому компьютеру. Привязка к `0.0.0.0` открывает доступ из сети: используйте её только в доверенной среде. Загрузка зависимостей и моделей требует интернет; работа уже загруженных моделей и собранного APK — локальная.

Основной целевой вариант — Windows x64. Для Linux нужны совместимые manylinux-библиотеки, в том числе glibc не старее 2.27; наличие Vulkan-драйвера необходимо для Vulkan. Для текущих колёс `tesserocr` на macOS требуется macOS 15 или новее. Windows ARM и остальные комбинации окружения не проверены и могут не иметь готовых Python-пакетов. Скрипт устанавливает только готовые колёса, не компилирует C++ и проверяет импорт OpenCV headless.

## Локальный ИИ

В панели выберите Qwen2.5 3B или 7B Q4_K_M и нажмите «Запустить модель». Сначала проверяется локальная Ollama; если она доступна, модель используется или загружается через неё. Иначе скачиваются официальный предварительно собранный `llama-server` из релизов llama.cpp и GGUF модели Qwen с Hugging Face; предусмотрены резервные источники. Размер 3B — около 2,1 ГБ, 7B — около 4,7 ГБ, причём официальный GGUF 7B состоит из двух файлов. Для комфортной работы потребуются несколько гигабайтов свободной оперативной памяти сверх размера модели; скорость зависит от компьютера. Прогресс и ошибки видны в панели. Загрузки GGUF проверяются по SHA-256; архив движка проверяется по сумме, опубликованной в GitHub Release, если она доступна.

Свой совместимый GGUF можно положить в `models/` и выбрать в списке. Если модель разбита на файлы, положите все части рядом и выбирайте первый файл. CPU — наиболее совместимый режим; Vulkan зависит от драйвера и официальной сборки для платформы. При недоступности загрузки можно вручную поместить содержимое официального архива `llama-server` вместе со всеми библиотеками в `runtime/llama/<система>-<архитектура>/<cpu или vulkan>/`, например `runtime/llama/windows-x86_64/cpu/`. Ollama можно использовать как альтернативу.

Запросы идут только к локальной Ollama или локально запущенному `llama-server`. Ответ ограничивается JSON Schema и дополнительно проверяется в Python. Несоответствующий JSON и правки за пределами выбранного экрана не применяются. Чтобы случайно не потерять текст, поля, которые из-за ограничения контекста показаны ИИ не полностью, нельзя заменить через ИИ; используйте ручной редактор. Нейросеть может ошибаться и не подтверждает безопасность работы: **значения, последовательности и меры безопасности всегда сверяйте с оригинальным руководством**.

## PDF и OCR

В «Разработчике» выберите PDF, при необходимости включите OCR и ИИ-объяснения. По умолчанию OCR выполняется на страницах с малым количеством извлечённого текста. Используются PDFium/pdfplumber, локальный кириллический RapidOCR PP-OCRv3 ONNX и Tesseract `rus+eng`. Для основного текста предпочтён Tesseract, когда он смог прочитать страницу; результат ONNX сохраняется отдельно в исходных данных и служит альтернативой. Если Tesseract не вернул достаточно текста, применяется результат ONNX. Все движки работают локально.

Оригинальный PDF, исходный текст и таблицы каждой страницы, альтернативный ONNX-текст, превью и найденные иллюстрации сохраняются в `data/documents/`. В дереве машины есть ссылки на оригинал и сырые данные, а в галерее можно выбрать иллюстрацию или выделить прямоугольник страницы. OCR и извлечение таблиц не гарантируют полноты или точности, особенно для плохих сканов и сложных таблиц. Разделы с недостаточными данными показывают предупреждения; проверяйте детали и числа вручную. Ограничения: до 150 МБ и 500 страниц на PDF.

ИИ-обработка PDF необязательна. При её включении материал отправляется в локальную модель пакетами по разделам. Исходные тексты не заменяются объяснениями; при ошибке модели извлечённые данные и предупреждение сохраняются.

## Редактор и APK

В режиме «Пользователь» работает тот же веб-интерфейс, что в Android-оболочке. Откройте машину, раздел, шаг или деталь; задайте запрос ИИ либо используйте «Править вручную». После изменения сохраняется текущий экран и доступна отмена последнего изменения в текущем сеансе. В дереве доступны фотография, изображения шагов, разделов, групп и деталей: файл, перетаскивание, вставка из буфера обмена или кадрирование из PDF.

«Собрать APK» упаковывает каталог и изображения в готовую оболочку, выравнивает ZIP и подписывает APK локальным RSA-2048/X.509 по APK Signature Scheme v2. Сборка работает без SDK, Java и интернета. В шаблоне `minSdk 24`, `targetSdk 36`, нет разрешений INTERNET и NETWORK; фактическая установка и совместимость зависят от устройства и не гарантируются.

**Важно:** первый запуск сборки создаёт приватный ключ и сертификат в `data/signing/`. Сохраните эту папку в надёжном месте и не публикуйте приватный ключ. Для установки нового APK поверх старого нужен тот же ключ; смена или потеря ключа потребует удаления старого приложения и может удалить его данные. Ключи не входят в архив проекта.

Каталог хранится в `data/project.json` и экспортируется в JSON. Оригиналы PDF и данные галереи в этот JSON не включаются: для полного переноса отдельно скопируйте `data/documents/` вместе с проектом, сохраняя идентификаторы папок. Папка `data/` не включена в исходный архив. JSON-импорт заменяет текущий каталог; отмена доступна, пока запущена студия.

## Проверки

Для расширенных тестов установите дополнительные зависимости:

```text
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python -m unittest discover -s tests -v
```

На Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`. Тесты проверяют криптографию APK v2, ZIP-выравнивание, каталог и изображения, манифест, PDF, кириллический OCR, безопасное применение правок и протокол локального ИИ. Без дополнительных пакетов тест манифеста и аудит синтаксических комментариев пропускаются. При наличии отдельно запущенного тестового `llama-server` на loopback можно дополнительно задать `KOLIBRI_TEST_LLAMA_PORT` для проверки реального schema-constrained ответа; это не проверка качества конкретной модели Qwen.

Для повторной сборки самой Android-оболочки исходники находятся в `sources/`; это отдельная разработческая задача, для которой понадобятся Node.js, Android SDK и Gradle. Обычная сборка пользовательского APK через студию в них не нуждается.

# Kolibri Python Studio

Локальный конструктор офлайн-справочника сельскохозяйственной техники: импорт руководств PDF, просмотр и редактирование каталога, локальный ИИ и сборка Android APK без Android SDK, Java, GitHub Actions или компилятора на этапе сборки. В комплекте — оболочка Android, её исходники и эталон ГРН-471: 8 групп и 124 позиции деталей.

## Быстрый запуск

1. Распакуйте архив в папку, в которой есть право записи.
2. Установите Python **3.10–3.12 x64** с `pip` и `venv`. На Windows используйте установщик с python.org и включите Python Launcher или добавление в PATH.
3. Windows: дважды нажмите `start.bat`. Linux/macOS: выполните `./start.sh`.
4. При первом запуске установятся Python-зависимости из PyPI. Откроется `http://127.0.0.1:8765/`. Оставьте окно терминала открытым; остановка — Ctrl+C.

Для принудительного запуска без браузера задайте `KOLIBRI_NO_BROWSER=1`. Для разработки можно изменить адрес и порт через `KOLIBRI_HOST` и `KOLIBRI_PORT`; по умолчанию сервер доступен только этому компьютеру. Привязка к `0.0.0.0` открывает доступ из сети: используйте её только в доверенной среде. Загрузка зависимостей и моделей требует интернет; работа уже загруженных моделей и собранного APK — локальная.

Основной целевой вариант — Windows x64. Для Linux нужны совместимые manylinux-библиотеки, в том числе glibc не старее 2.27; наличие Vulkan-драйвера необходимо для Vulkan. Для текущих колёс `tesserocr` на macOS требуется macOS 15 или новее. Windows ARM и остальные комбинации окружения не проверены и могут не иметь готовых Python-пакетов. Скрипт устанавливает только готовые колёса, не компилирует C++ и проверяет импорт OpenCV headless.

## Локальный ИИ

Первый профиль — «Kolibri Qwen2.5-3B Мехфак (дообученная по РЭ ГРН-471)». Он станет доступен **только после успешного обучения и публикации** [модели в GitHub Release](https://github.com/Igorr112323/CALIBRE/releases/tag/kolibri-ai-model). Если релиза ещё нет или публикация заблокирована, студия сообщает об этом; базовая модель под видом дообученной не подставляется. Профиль всегда использует `llama-server`, даже если установлена Ollama. Модель и её SHA-256 загружаются из одного релиза, после проверки сумма сохраняется рядом для автономного запуска; это проверка целостности, а не независимая цифровая подпись.

Профили базовых Qwen2.5 3B и 7B Q4_K_M также сохранены. Для них сначала проверяется локальная Ollama; если она доступна, модель используется или загружается через неё. Иначе скачиваются официальный `llama-server` и GGUF модели Qwen с Hugging Face; предусмотрены резервные источники. Размер базовой 3B — около 2,1 ГБ, 7B — около 4,7 ГБ, причём официальный GGUF 7B состоит из двух файлов. Для работы потребуются гигабайты свободной оперативной памяти сверх размера модели; скорость зависит от компьютера. Прогресс и ошибки видны в панели. Базовые GGUF проверяются по заранее известным SHA-256; архив движка — по сумме из GitHub Release, если она доступна.

**Improved using Qwen.** Qwen2.5-3B-Instruct распространяется по [Qwen Research License](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/blob/main/LICENSE): стандартное разрешение ограничено некоммерческими исследованиями и оценкой; для коммерческого использования необходима отдельная лицензия. Эти условия распространяются и на дообученную производную модель.

Свой совместимый GGUF можно положить в `models/` и выбрать в списке. Если модель разбита на файлы, положите все части рядом и выбирайте первый файл. CPU — наиболее совместимый режим; Vulkan зависит от драйвера и официальной сборки для платформы. При недоступности загрузки можно вручную поместить содержимое официального архива `llama-server` вместе со всеми библиотеками в `runtime/llama/<система>-<архитектура>/<cpu или vulkan>/`, например `runtime/llama/windows-x86_64/cpu/`. Ollama можно использовать как альтернативу.

Запросы идут только к локальной Ollama или локально запущенному `llama-server`. Ответ ограничивается JSON Schema и дополнительно проверяется в Python. В чате любые правки сначала готовятся на копии и показываются как сравнение «было / станет»; **пока вы не просмотрели предложение и не подтвердили сохранение, каталог не меняется**, даже если модель говорит «готово». Предложение можно отклонить. Оно хранится только в памяти до 30 минут и не применяется, если каталог изменился, студия перезапущена или предложение уже использовано; в этом случае отправьте запрос заново. Для слишком большого сравнения сохранение блокируется вместо скрытого сокращения.

На открытом шаге ИИ может предложить изменение или удаление только этого шага, а также добавление шага после него или в конец регулировки. Для изменения другого шага откройте его; заголовок регулировки редактируется на экране списка или вручную. Несоответствующий JSON, запрещённые пути и правки полей, показанных ИИ не полностью, отклоняются. При вставке и удалении шагов загруженные изображения сохраняют привязку к своим шагам; изображение удаляемого шага удаляется вместе с ним. В сравнении изображения обозначаются размером и контрольной суммой, а не отображаются целиком. Изменение текста не исправляет автоматически связанные схемы и старые пояснения — проверьте их отдельно.

Для некоторых чисел с единицами измерения, отсутствующих в показанном источнике и запросе, выводится предупреждение. Это лишь вспомогательная эвристика: она не обнаруживает все ошибки, неверные направления, единицы или опасные инструкции. Нейросеть может ошибаться и не подтверждает безопасность работы: **значения, последовательности и меры безопасности всегда сверяйте с оригинальным руководством**.

## PDF и OCR

В «Разработчике» выберите PDF, при необходимости включите OCR и ИИ-объяснения. По умолчанию OCR выполняется на страницах с малым количеством извлечённого текста. Используются PDFium/pdfplumber, локальный кириллический RapidOCR PP-OCRv3 ONNX и Tesseract `rus+eng`. Для основного текста предпочтён Tesseract, когда он смог прочитать страницу; результат ONNX сохраняется отдельно в исходных данных и служит альтернативой. Если Tesseract не вернул достаточно текста, применяется результат ONNX. Все движки работают локально.

Оригинальный PDF, исходный текст и таблицы каждой страницы, альтернативный ONNX-текст, превью и найденные иллюстрации сохраняются в `data/documents/`. В дереве машины есть ссылки на оригинал и сырые данные, а в галерее можно выбрать иллюстрацию или выделить прямоугольник страницы. OCR и извлечение таблиц не гарантируют полноты или точности, особенно для плохих сканов и сложных таблиц. Разделы с недостаточными данными показывают предупреждения; проверяйте детали и числа вручную. Ограничения: до 150 МБ и 500 страниц на PDF.

ИИ-обработка PDF необязательна. При её включении материал отправляется в локальную модель пакетами по разделам. Исходные тексты не заменяются объяснениями; при ошибке модели извлечённые данные и предупреждение сохраняются. Пакет объяснений также отклоняется, если в нём обнаружены числа или некоторые единицы измерения, отсутствующие в соответствующем исходном пункте. Эта проверка не гарантирует смысловую и техническую правильность пояснения.

## Редактор и APK

В режиме «Пользователь» работает тот же веб-интерфейс, что в Android-оболочке. Откройте машину, раздел, шаг или деталь; задайте запрос ИИ либо используйте «Править вручную». После изменения сохраняется текущий экран и доступна отмена последнего изменения в текущем сеансе. В дереве доступны фотография, изображения шагов, разделов, групп и деталей: файл, перетаскивание, вставка из буфера обмена или кадрирование из PDF.

«Собрать APK» упаковывает каталог и изображения в готовую оболочку, выравнивает ZIP и подписывает APK локальным RSA-2048/X.509 по APK Signature Scheme v2. Сборка работает без SDK, Java и интернета. В шаблоне `minSdk 24`, `targetSdk 36`, нет разрешений INTERNET и NETWORK; фактическая установка и совместимость зависят от устройства и не гарантируются.

**Важно:** первый запуск сборки создаёт приватный ключ и сертификат в `data/signing/`. Сохраните эту папку в надёжном месте и не публикуйте приватный ключ. Для установки нового APK поверх старого нужен тот же ключ; смена или потеря ключа потребует удаления старого приложения и может удалить его данные. Ключи не входят в архив проекта.

Каталог хранится в `data/project.json` и экспортируется в JSON. Оригиналы PDF и данные галереи в этот JSON не включаются: для полного переноса отдельно скопируйте `data/documents/` вместе с проектом, сохраняя идентификаторы папок. Папка `data/` не включена в исходный архив. JSON-импорт заменяет текущий каталог; отмена доступна, пока запущена студия.

## Проверки

Для расширенных тестов установите дополнительные зависимости:

```text
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python -m unittest discover -s tests -v
```

На Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`. Тесты проверяют криптографию APK v2, ZIP-выравнивание, каталог и изображения, манифест, PDF, кириллический OCR, безопасное применение правок и протокол локального ИИ. Без дополнительных пакетов тест манифеста и аудит синтаксических комментариев пропускаются. При наличии отдельно запущенного тестового `llama-server` на loopback можно дополнительно задать `KOLIBRI_TEST_LLAMA_PORT` для проверки реального schema-constrained ответа; это не проверка качества конкретной модели Qwen.

Для отдельной проверки семи реальных ответов уже запущенной модели предусмотрен `tests/evaluate_real_model.py`:

```text
.venv/bin/python tests/evaluate_real_model.py --port 18948 --out model-review.json
```

Укажите фактический порт своего `llama-server`; отчёт содержит ответы и правки, применённые только к копии примера, не к вашему каталогу. Можно передать `--model-file путь/к/модели.gguf` для вычисления SHA-256 и `--case exact_number_edit` для отдельного сценария. Название модели берётся с сервера; хеш указанного файла сам по себе не доказывает, что именно этот файл загружен сервером. Автоматические проверки неполны и могут ошибаться — все результаты необходимо дополнительно прочитать. Пример проведённой проверки и ограничения описаны в `AI_EVALUATION.md`.

Для повторной сборки самой Android-оболочки исходники находятся в `sources/`; это отдельная разработческая задача, для которой понадобятся Node.js, Android SDK и Gradle. Обычная сборка пользовательского APK через студию в них не нуждается.

## Обучение и выпуск модели

В `training/` находятся проверяемый генератор 348 примеров, скрипты обучения и конвертации, экзамен и блокировка выпуска. При генерации 124 позиции из восьми групп сравниваются непосредственно с таблицами прилагаемого РЭ, а выдержки — с текстом соответствующих страниц. Пояснения `purpose` и `inspection` эталона не используются как заводские факты. Модели показываются сокращённые контексты и исходный системный промпт; дополнительные правила чата в реальной студии остаются без изменений, но целиком не помещаются в учебный лимит 448 токенов. Пользовательские каталоги и папка `data/` в обучение не входят.

Workflow `.github/workflows/train-kolibri-gguf.yml` предназначен для Ubuntu CPU: BF16, LoRA r16/alpha32 на верхней трети слоёв, четыре потока и измерение первых трёх шагов. Целевые 32 минуты не гарантированы: выполняется минимум один проход по всем примерам, даже если расчётная длительность больше. Отчёт loss сравнивает одну и ту же небольшую подвыборку **из обучающих данных** и не является независимым экзаменом. После объединения адаптера выполняются конвертация в GGUF и Q4_K_M, затем исходные семь сценариев и дополнительные проверки на запущенном `llama-server`. Диагностика сохраняется как artifact Actions даже при провале проверки, когда это позволяет состояние задания.

Выпуск блокируется, если не совпадают исходная модель и конфигурация, не пройден полный набор данных, не снизился диагностический loss, не прошли все эвристики экзамена, SHA-256 не совпадает или размер GGUF **не меньше 1 950 000 000 байт**. Последнее ограничение принципиально: официальный Qwen2.5-3B Q4_K_M имеет размер 2 104 932 768 байт, а LoRA не уменьшает архитектуру. Поэтому выпуск указанного формата и лимита заранее не гарантирован и, вероятно, будет заблокирован. Эвристики сами по себе не гарантируют корректность или безопасность ответов. Подробности запуска и проверок приведены в `training/README.md`.

- Модель кириллического распознавания PaddleOCR PP-OCRv3 ONNX: Apache 2.0; SHA-256 `1efb65bdc460af1c0e8733d005b20952b17ca5aac10ddb56c968333791c5eaa3`. Источник модели: RapidAI/RapidOCR; копия получена из `mustafa-mahmud/ocr-models` и совпадает с опубликованной суммой RapidOCR.

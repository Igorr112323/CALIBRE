# Исследовательское обучение Kolibri Qwen2.5-3B

**Improved using Qwen.** Базовая модель `Qwen/Qwen2.5-3B-Instruct` распространяется по [Qwen Research License](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/blob/main/LICENSE). Стандартная лицензия ограничена некоммерческими исследованиями и оценкой; для коммерческого использования необходима отдельная лицензия. При публикации workflow прикладывает исходный текст лицензии и `NOTICE.txt`, описывающий изменение модели.

## Данные

`build_dataset.py` принимает только проверенные по SHA-256 копии `examples/РуководствоПоГраблям.pdf` и `examples/sample-catalog.json`. Он сверяет наименование, обозначение, количество и примечание всех 124 позиций по соответствующим строкам таблиц PDF; для 79 подготовленных фактов проверяет наличие выдержки на указанной странице. Подготовленные ответы и перефразирования нужно оценивать по смыслу: поиск выдержки сам по себе не доказывает их корректность.

Генерируются 376 примеров: **325 для обучения и 51 для контроля**. Страницы PDF, использованные в отложенной выборке (`13`, `20`, `27`, `49`), не используются в обучающей, включая ссылки на источник заменяемого числа. Точные готовые ответы и идентификаторы также не пересекаются. При этом встречаются общие формулировки запросов и семантически близкие факты, а обе выборки синтетические и созданы одним генератором. Снижение loss на них не равно независимому подтверждению практического качества.

В выборках присутствуют вопросы о руководстве и деталях, объяснения, запрошенные правки и добавления, отказы, отсутствие данных и инструкции, внедрённые в исходный текст. Для числовой правки новое значение представлено как запрос пользователя, **не как заводская норма**; известные примеры ослабления ограничений скорости и безопасности в число таких правок не включены. Пояснения `purpose` и `inspection` выбранной детали в учебном контексте очищаются: они не подтверждены PDF. Ни пользовательские каталоги, ни папка `data/` в обучение не входят.

```text
python python_studio/training/build_dataset.py
```

Результаты — `train.jsonl`, `validation.jsonl` и `dataset-manifest.json` с контрольными суммами. Генерация детерминирована. Для каждого синтетического запроса контекст создаётся функцией `selected_context`, а полный системный промпт и сообщение — функцией `chat_messages`, как в реальной Studio. Выбранные поля, а не вся пользовательская база, составляют контекст. Для этого варианта установлен предел 2048 токенов; обучение останавливается с ошибкой, если какой-либо пример длиннее, вместо обрезания ответа или инструкций. Точные инструкции 12 экзаменационных сценариев не копируются в обучающую и контрольную выборки.

## Запуск

Workflow `.github/workflows/train-kolibri-gguf.yml` запускается при изменении обучения в ветке `arena/0d487d0e-calibre` или вручную, когда GitHub разрешает запуск workflow из выбранной ветки. Выполнение требует доступа к Hugging Face и CPU runner Ubuntu 24.04; включается файл подкачки 8 ГБ. Веса и промежуточные файлы не коммитятся. Для локального запуска нужны Python 3.11, CPU-сборка PyTorch 2.6.0 и зависимости `requirements-training.txt`:

```text
python python_studio/training/build_dataset.py
python python_studio/training/train_kolibri_gguf.py --threads 4 --max-length 2048 --target-minutes 32 --max-epochs 2 --learning-rate 0.00005 --output /path/to/work
python python_studio/training/train_kolibri_gguf.py --convert-only --output /path/to/work --llama-source /path/to/llama.cpp --quantize /path/to/llama-quantize --quantization Q3_K_M --threads 4
```

Используются веса Qwen2.5-3B-Instruct ревизии `aa8e72537993ba99e69dfaafa59ed015b17504d1`, BF16 на CPU и LoRA r16/alpha32 в семи проекциях слоёв 24–35 из 36. Последовательности не дополняются до общей длины; loss вычисляется только по токенам ответа. Первые три шага измеряются и дают приблизительную оценку продолжительности. Планируются только полные проходы: если по этой оценке два прохода не укладываются в целевые 32 минуты, выполняется один. Первый проход не прерывается ради целевого времени; проверка loss, сохранение, квантование и экзамены занимают дополнительное время. При длинном контексте ориентир 25–40 минут не гарантирован и может быть значительно превышен. Весь job ограничен шестью часами; при его отмене релиз не создаётся. `--max-steps` предназначен для неполной проверки механики и не допускается к выпуску.

Loss измеряется на всех 51 отложенных примерах до обучения и после каждой полной эпохи. Если улучшение прекращается, обучение останавливается; затем восстанавливается лучший обученный адаптер, повторно измеряется loss и сверяются SHA-256 его выбранных и восстановленных весов. В метриках записываются отдельные значения loss, причина остановки, выбранный шаг и параметры адаптера; журнал фиксирует каждый учебный пример. Эти записи создаёт сам обучающий скрипт: проверки не являются независимой криптографической аттестацией вычислений. Затем адаптер объединяется с базовой моделью и конвертируется закреплённым llama.cpp `b7571`. Строятся основной `Q3_K_M` и, по возможности, альтернативный `Q4_K_S` из того же BF16 GGUF.

## Экзамен и ограничения публикации

`evaluate_candidates.py` по очереди запускает `llama-server` с конкретным файлом каждого доступного варианта. `evaluate_finetuned.py` выполняет семь исходных сценариев и пять дополнительных проверок устройства, отсутствующих сведений и сохранения безопасности. Вычисляется SHA-256 файла и сверяется имя модели сервера. Сам API сервера не является криптографическим доказательством происхождения модели. Отчёт содержит фактические ответы и изменения на копии примера. Локальный smoke на маленькой случайной модели не является экзаменом дообученной 3B.

`verify_release.py` запрещает публикацию, если не совпадают исходная модель, архитектура, шаблон чата или SHA источников; если обучающая и отложенная выборки пересекаются по страницам, идентификаторам или готовым ответам; если журнал не подтверждает полный проход, адаптер не изменился, не восстановлен лучший checkpoint или loss на отложенной выборке не снизился. Также обязательны все **12/12** эвристических проверок и размер GGUF строго менее **1 950 000 000 байт**. Целевой размер Q3 менее 1 700 000 000 байт желателен, но отдельным обязательным воротом не является. Из прошедших все проверки вариантов при равном результате выбирается Q3_K_M; если ни один вариант не прошёл, публикации нет.

`release-gate.json` и artifact `kolibri-qwen-training-diagnostics` содержат размеры, loss, причины отказа, ответы и результаты каждого сценария, когда состояние задания позволяет их получить. Сжатые аннотации дублируют диагностику при доступном GitHub Actions. При подготовке выпуска повторно сверяются SHA-256 модели, отчёта, журнала, выборок, фактов, метрик и manifest; журнал включается в контрольные суммы релиза. Release с тегом `kolibri-ai-model` создаётся как черновик и становится публичным только после проверок; существующий релиз скрипт не перезаписывает.

## Измеренные результаты, не текущий релиз

Run [43511938080](https://github.com/Igorr112323/CALIBRE/actions/runs/43511938080) построил Q4_K_M размером 1 929 903 008 байт, но провалил экзамен: 1/7 исходных и 2/5 дополнительных сценариев. В следующем [run 43567132776](https://github.com/Igorr112323/CALIBRE/actions/runs/43567132776) Q3_K_M размером 1 590 475 680 байт прошёл 0/7 и 0/5, Q4_K_S размером 1 834 384 288 байт — 1/7 и 3/5. Оба выпуска заблокированы. Это старые результаты обучения на сокращённом промпте и контрольной подвыборке из обучающих данных; позже эвристики были уточнены, поэтому числа не полностью сопоставимы с новыми проверками. Подробные ответы сохранены в `diagnostics/`.

Повторная проверка **базовой, не дообученной** модели [43577154074](https://github.com/Igorr112323/CALIBRE/actions/runs/43577154074) дала Q3 0/7 и 0/5, Q4_K_S и Q4_K_M по 2/7 и 3/5. На всех 12 запросах шаблоны и токены Hugging Face и llama.cpp совпали; это не устанавливает причину ошибок Q3. В отдельной диагностике [43579807337](https://github.com/Igorr112323/CALIBRE/actions/runs/43579807337) SHA чистого Q3 совпал с baseline. Автоматические оценки четырёх новых запросов: полный промпт Studio 0/4, сокращённый русский 1/4, сокращённый английский 1/4, английский с примерами 0/4, Studio без JSON-ограничения 0/4. Ручной просмотр обнаружил, что оба автоматических зачёта ложные: один ответ копирует исходный текст, другой искажённо повторяет запрос. В одном свободном ответе модель верно отметила отсутствие давления, но не вернула обязательный JSON. Полный отчёт — `../baseline/diagnostics/independent-q3-run-43579807337.json`.

Ни снижение loss, ни все эвристики не гарантируют точность или безопасность. Ручная проверка по РЭ обязательна. Пока релиза модели нет, первый профиль студии сообщает, что она не опубликована, и не подставляет базовую модель под видом дообученной.

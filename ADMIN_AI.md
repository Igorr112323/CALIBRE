# Kolibri: локальная база документов и технический помощник

## Что меняется и что остаётся нетронутым

Эта часть относится к **админ-панели и серверу на ПК**. Мобильные файлы `mobile/` не изменяются: действующие экран, дизайн, ресурсы и APK не пересобираются этой работой. Серверный мобильный API отдельно продолжает отдавать только опубликованный каталог; API документов и админки закрыт для запросов из локальной сети.

Админ-панель открывается на компьютере-сервере по адресу `http://127.0.0.1:8765/admin`. Карточки техники, PDF, изображения и извлечённые страницы лежат в локальном хранилище сервера (`CALIBRE_DATA_DIR`, в готовом EXE — `%LOCALAPPDATA%\CALIBRE`). Сам PDF не добавлен в Git и не включён в программный архив.

## Начальная загрузка граблей Kolibri

1. Создайте карточку `GRN-471 / Kolibri / ГРН-471 / Грабли`.
2. Загрузите официальный PDF через «Документы и фото».
3. Для руководства по ГРН-471 v4 распознаётся контрольная сумма исходного PDF; диапазоны устанавливаются как **руководство: PDF-стр. 4–33**, **каталог запчастей: PDF-стр. 34–56**. Для других документов диапазоны можно задать вручную.
4. PDF извлекается постранично. Страницы без текстового слоя остаются помеченными как требующие визуальной проверки. Загрузка фотографий сохраняет их локально и подпись, но сама по себе **не означает, что ИИ распознал изображение**.
5. Карточки техники и документы не попадают в APK автоматически и не публикуются без отдельного утверждения.

## Как работает помощник

Поиск выполняется локально по страницам: русская нормализация/стемминг и ранжирование релевантных фрагментов. Каталог деталей исключён из ответов по регулировкам и нормативам; по явному запросу о запасных частях каталог можно искать отдельно.

Генеративная модель подключается через совместимый с OpenAI Chat Completions API endpoint. Модель не переобучается на документах: система передаёт ей только найденные отрывки (RAG), требует цитировать их и не додумывать неизвестные нормы. Перед показом ответа сервер проверяет, что каждая цитата находится на выданной странице, а числа из ответа встречаются в процитированном тексте. Вопросы о снятой защите/ремонте при работающем двигателе дополнительно проверяются на наличие процитированного запрета. При сбое, отсутствии источника или подключённой модели ответ блокируется, а не маскируется под ответ ИИ.

Для точной контрольной суммы GRN-471 v4 при загрузке локально строится структурированный граф каталога: «рисунок/позиция → обозначение/название/количество → сборка → функция и источник». Граф индексирует каждую каталожную строку, а для функции различает прямое описание детали, роль только всей сборки и отсутствие индивидуального назначения. Вопросы о деталях передаются модели вместе с этой связью и исходными страницами. Если руководство не подтверждает индивидуальную функцию, помощник называет этот пробел и не переносит функцию узла на отдельный крепёж или подшипник. Для 85 позиций с описанным только контекстом сборки и 27 позиций без индивидуального назначения добавлены отдельные инженерные гипотезы по каталоговому названию и взрыв-схемам, с уровнем уверенности и ссылкой на страницу рисунка. Каждая помечена как не подтверждённая изготовителем; её нельзя считать цитатой из руководства или применять как инструкцию по регулировке, ремонту, безопасности или взаимозаменяемости. Это ручная детерминированная экспертная база/логика, не обучение нейросети и не LLM. Windows EXE включает эту логику и админку, но не включает PDF и не подменяет источник: руководство загружается владельцем локально на ПК.

### Подключение модели

Для локального OpenAI-совместимого сервера задайте переменные **до запуска** Windows EXE:

```powershell
$env:CALIBRE_AI_BASE_URL = "http://127.0.0.1:11434/v1"
$env:CALIBRE_AI_MODEL = "имя-модели-в-вашем-сервере"
$env:CALIBRE_AI_API_KEY = ""   # только если выбранный локальный сервер требует ключ
.\dist\CALIBRE-PC.exe
```

Имена сервера и модели зависят от установленного пользователем AI endpoint; в поставку модель и ключ не входят. Внешний endpoint заблокирован по умолчанию. Если владелец сознательно разрешает удалённую модель, дополнительно задаётся `CALIBRE_AI_ALLOW_REMOTE=1`; тогда передаваемые фрагменты документации покидают ПК. Для удалённого endpoint используйте HTTPS и не добавляйте секреты в Git или чат.

**Сейчас генеративный endpoint в среде разработки не подключён.** Поэтому рабочая часть — загрузка документов, локальный поиск и строгий контроль ответов; фактическое качество ответов конкретной модели ещё не измерялось.

## Жёсткие проверки

Официальный PDF для внутренних тестов лежит только в Git-ignored каталоге `tests/test_documents/GRN-471-Kolibri-v4.pdf`.

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -q
.venv/bin/python tools/run_grn471_stress.py
.venv/bin/python tools/check_grn471_benchmark.py --audit-gold
.venv/bin/python tools/evaluate_grn471_parts.py
```

Стресс-набор включает поломки и неисправности, безопасность без ограждений и при работающем двигателе, отсутствующие зазор/момент затяжки, диапазоны транспортирования, смазку, подмену нормативов каталогом и запрос с prompt injection. Отдельные тесты подменяют AI endpoint и проверяют отказ на выдуманные числа/цитаты и небезопасные ответы — это не считается испытанием реальной модели.

Последняя локальная проверка: **12/12** сценариев извлечения нужных страниц прошли; каталог не просочился в сценарии регулировок. Автоматическая сверка чернового числового эталона с PDF: **59/63** нормы подтверждены текстовым слоем, **4** оставлены на ручную визуальную проверку/сверку; не прошедших цитат — **0**. Часть схем и пиктограмм не представлена в PDF текстом. Эталон остаётся черновиком до одобрения владельцем; эти результаты не являются оценкой подключённой LLM и не гарантируют абсолютную безошибочность.

### Охват каталога запчастей

Для точного файла v4 локальный аудит извлекает **124 отдельные позиции** из спецификаций рисунков 1–9 (рисунки 1 и 2 используют одну общую спецификацию), связывает каждую с обозначением/названием, количеством, позицией, сборкой и PDF-страницей. В проверенном черновике: **12/124** позиций имеют отдельную функцию, подтверждённую текстом; **85/124** имеют только подтверждённый контекст узла (функцию узла нельзя приписывать детали); у **27/124** индивидуальная функция и конкретная под-сборка из руководства не установлены. В каталоге **64** строки с пустой отдельной ячейкой обозначения, но их наименование/стандарт сохранены из соседней ячейки таблицы. Схематичный указатель и дубликаты обозначений не объединяются без доказательства.

Из 20 групп компонентов, названных в руководстве, 19 имеют цитируемое функциональное описание или осторожно ограниченный контекст узла; для «Опоры» отдельное назначение не найдено. Отдельно отмечены как неразрешённые связи: опора на общем виде не найдена отдельной спецификационной позицией; транспортная распорка описана в руководстве, но не найдена как отдельная строка в извлечённых спецификациях, и её нельзя автоматически путать с распоркой механизма ограждений. Числа **124 / 12 / 85 / 27** — результат проверки покрытия индекса, не оценка модели и не одобрение владельца.

Запустить аудит источника (PDF нужен только в игнорируемом локальном каталоге):

```bash
.venv/bin/python tools/evaluate_grn471_parts.py
```

Граф и отчёт сохраняются в `tests/test_documents/runs/`, не включаются в Git. Локальный upload создаёт тот же граф внутри базы данных ПК-сервера. Данный черновик ещё должен пройти проверку/одобрение владельца; по реальной LLM **оценки пока нет**.

## Текущие ограничения

- Изображения и диаграммы сохраняются; распознавание деталей на них, OCR сканов и ответы по картинкам ещё не подключены. Такие страницы нельзя автоматически считать проверенными.
- Числовой фильтр не доказывает, что модель правильно связала число с нужной строкой таблицы; для выпуска нормативов всё равно требуется проверка эталоном и человеком.
- Автоматический поиск не равен обучению модели или гарантии «идеального» ответа. Перед практической эксплуатацией нужно подключить выбранную модель, прогнать тот же стресс-набор уже по её ответам и проверить результаты на ПК.

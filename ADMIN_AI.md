# ГРН-471 Kolibri v4 — локальный демо-срез этапов 4–6

Это ограниченная проверка загрузки документа, локального анализа, проверки карточек и публикации для одной рабочей машины. Она не является полной базой руководств, сертифицированной инструкцией или обученной языковой моделью.

## Границы изменений

- Экранная структура, цвета, шрифты, компоновка, анимация, иконка и заставка APK из `stage3-test-19` остаются замороженными. Разрешено только заполнить существующие области подготовленным контентом и добавить авторизованную нажимаемую SVG-схему во вкладку «Схема». Вопросы к документу доступны только в ПК-админке.
- APK включает подготовленный текстовый каталог **«ГРН-471 Kolibri (демо)»**. PDF и извлечённые изображения/кропы не включаются ни в Git, ни в APK/EXE/релиз; владелец загружает PDF локально на ПК.
- Мобильный серверный API отдаёт телефону только опубликованный каталог, не PDF и не черновики. Фото `internal_only` можно явно разрешить для LAN-sync в админке: кэшированная копия передаётся только через мобильный LAN endpoint и только для опубликованного узла; фото остаётся непубличным и не выходит в веб/API каталога за пределами этой локальной сети. Очередь обратной связи сохраняется локально и отправляется при восстановлении связи; каталог и разрешённые фото доступны офлайн.
- Админка — на loopback компьютера. LAN-слушатель EXE предназначен для ограниченного мобильного API; админка и PDF-файлы не открываются телефону.

## PDF, анализ и восстановление

Для распознанного точного файла Kolibri v4 области по умолчанию: руководство — PDF-стр. 4–33; каталог деталей — PDF-стр. 34–56. Для любого другого PDF диапазоны задаются вручную. Каталог деталей используется для названий и связей компонентов, но не служит источником эксплуатационных регулировок.

После локальной загрузки сохраняются исходный PDF, извлечённый текст постранично и состояние `AnalysisRun`. Разбор разделён на этапы, сохраняет промежуточные ответы и может продолжиться после остановки приложения. Пока подходящая модель недоступна, run остаётся в состоянии ожидания, а подготовленные данные, просмотр и лексический поиск доступны. Ошибки распознавания/модели не превращаются в утверждения.

Администратор видит карточки с типом, статусом проверки, страницей и цитатой, может редактировать или отклонять. Изменение карточки сбрасывает человеческое подтверждение. Публикация числовой нормы блокируется, если цитата не найдена на указанной странице или число не подтверждено программной проверкой. Числовую карточку с ошибкой машинной проверки нельзя одобрить обходным «ручным» подтверждением. Перед публикацией система блокирует конфликтующие числовые значения с одинаковым названием и условием и пропускает уже имеющиеся совпадающие нормы. Пробелы руководства помечаются как требующие проверки человеком.

Цитаты в админке открывают отрисованную из локального PDF страницу; цитата отдельно сверяется с текстом страницы и, когда PDFium находит координаты, подсвечивается поверх изображения страницы. Отсутствие подсветки не считается подтверждением — UI явно предупреждает о ручной проверке.

## Только локальные модели Ollama

В админке предусмотрена локальная интеграция Ollama без облачного fallback:

- чат/извлечение: `qwen3:8b`;
- embedding-поиск: `bge-m3`.

Имена моделей можно заменить; загрузка возможна через установленный Ollama. Модельные веса не включаются в EXE/APK. Для первичной загрузки весов требуется подключение; последующий анализ и вопросы идут через loopback `127.0.0.1:11434` и не требуют сети. Без Ollama остаются подготовленный текстовый каталог, локальный поиск и просмотр PDF; генеративные ответы не имитируются.

Ответ модели получает только извлечённые страницы. Перед отображением программно проверяются принадлежность цитаты странице и наличие чисел ответа в процитированном тексте. Для вопросов безопасности дополнительно требуется цитата запрета. При неверной цитате, числе или сбое ответ блокируется. Это не заменяет экспертную проверку контекста таблицы.

## Объём контента и gold-проверка

Демо включает подготовленные материалы по узлам рисунка 1.1 и раздела 2.3; регулировкам разделов 2.3/5/6; безопасности; строкам таблицы 10.1; ЕТО, хранению и смазке. Пробелы руководства, включая отсутствие абсолютной нормы высоты граблин над землёй, сохраняются отдельной пометкой, а не заполняются типовой нормой.

Локальный эталон и исходный PDF хранятся в игнорируемом `tests/test_documents/` и не публикуются. Инструменты `tools/check_grn471_benchmark.py` и `tools/run_grn471_stress.py` сравнивают найденные/пропущенные/лишние/неподтверждённые утверждения и числа. Перед отчётом нужно заново выполнить аудит против локального PDF; целевой критерий — ноль выдуманных чисел и не менее 90% ожидаемых норм, проходящих машинную проверку. До завершения проверки реальной LLM по gold и локального PDF нельзя заявлять достигнутый процент.

## Проверки

```bash
.venv/bin/python -m compileall -q calibre server.py desktop_launcher.py migrations/versions
.venv/bin/python -m unittest discover -s tests -v
node --check web/admin/admin.js
node --check web/admin/pdf-viewer.js
```

GitHub Actions workflow `.github/workflows/build-android.yml` вручную собирает Android APK и Windows EXE, запускает Windows self-test, считает SHA-256 и публикует единый prerelease с прямыми файлами. `build-windows-expert.yml` запускает дополнительную Windows-проверку и сохраняет артефакт. Успешные unit-тесты не равны успешной сборке Windows/Android и не заменяют физическую проверку владельцем.
